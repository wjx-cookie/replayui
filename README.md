# Replay UI

让 Flashback 回放里的**容器界面**（背包、箱子、工作台、熔炉……）也能重现。

默认状态下，Flashback 能回放快捷栏和装备，但打不开的背包和箱子——因为打开容器需要服务端配合，而回放里的"服务端"是虚拟的。本模组在录制时把界面状态一并存进回放文件，回放时以**原版方式**把真正的界面重建出来。

因为重建出的是货真价实的 `AbstractContainerScreen`，任何按常规方式工作的模组容器都能被录制，无需逐个适配。

## 一、安装

### 需要准备

| 组件 | 版本要求 | 说明 |
|---|---|---|
| Minecraft | 1.21.1 | 其他版本需另行构建 |
| Fabric Loader | 0.15+ | |
| Fabric API | 任意 | |
| **Flashback** | **0.39.0+** | 必需，本模组是它的扩展 |
| Spatial GUI | 可选 | 装了才有 3D 面板效果 |

**Flashback 是必需的**。它不在 Maven 上，本模组无法自动附带，请自行从官方渠道获取。

### 安装步骤

把以下三个文件**平级**放进 `mods/` 文件夹：

```
mods/
├── replayui-0.1.0.jar
├── flashback.jar
└── fabric-api.jar
```

Spatial GUI 如果要用，同样平级放进去即可。

## 二、使用方法

不需要任何配置，装上就能用。

**录制**：正常开启 Flashback 录制。录制期间打开背包或箱子，界面状态会自动被记录，包括里面的物品和鼠标位置。

**回放**：打开录制好的回放。当你观看的玩家打开容器时，界面会自动出现，并跟随录制内容自动关闭。

界面是**只读**的——点击、拖拽、按键都不会产生任何效果，不会向回放服务端发送任何数据包。

想临时关掉当前界面，按 **Esc** 或 **E** 即可；在录制内容变化之前，它不会自动重新弹出。

### 配合 Spatial GUI

装上 Spatial GUI 后，重建出的界面会被它识别为普通容器界面，自动渲染成世界中的 3D 悬浮面板，第三人称和自由运镜下都能看到，鼠标悬停、物品提示等也照常工作。

没装 Spatial GUI 也能正常使用，只是以普通的 2D 界面呈现。

## 三、常见问题

### 界面没有出现

先确认：回放是**在装有本模组的情况下录制的**。旧回放里没有界面数据，本模组无法凭空补上。

然后看日志，搜索 `replayui`：

| 日志内容 | 说明 |
|---|---|
| 没有任何 `replayui` 输出 | 模组没加载。检查 Flashback 是否安装、版本是否 ≥0.39.0 |
| 有 `received UI data from replay` | 数据链路正常，问题在后面，继续看有没有 warn |
| 没有 `received UI data from replay` | 数据没录进去，检查录制时本模组是否在工作 |

### 日志里的 warn 都是什么意思

| 提示 | 原因 | 处理 |
|---|---|---|
| `menu type id N is not registered` | 回放里用了你没装的模组容器 | 装上对应模组，或忽略 |
| `slot count mismatch` | 用其他 MC 版本打开了这个回放 | 换回录制时的版本 |
| `no screen factory registered` | 该菜单没有客户端界面 | 罕见，多为纯逻辑菜单 |

日志位置：游戏目录下 `logs/latest.log`。

### 需要更详细的日志吗

加 JVM 参数 `-Dreplayui.debug=true` 可开启逐 tick 的详细输出（默认关闭，因为会刷屏）。

## 四、已知限制

- **面板位置**：多人回放中，3D 面板可能挂在观看者身上而非被录玩家面前。相关开关 `syncYaw` 默认关闭，因其实测效果尚未确认。
- **只录自己的界面**：客户端只能看到自己的背包和容器，其他玩家的界面无法录制。要录全员需要服务端录制方案。
- **跨版本**：回放文件与录制时的 MC 版本绑定，换版本打开可能因槽位数变化而跳过界面。
- **只能录制**：录制时打开的界面才会被记录；回放中无法凭空"打开"一个新容器。

## 五、从源码构建

### 1. 准备 Flashback jar

Flashback 不在 Maven 上，且为 ARR 许可（保留所有权利），**不能随项目分发**。

下载 0.39.9 的 jar，放到 `libs/flashback-0.39.9.jar`（该目录内有说明文件）。

### 2. 构建

```
gradle wrapper        # 首次，让 Gradle 生成 wrapper 脚本
./gradlew build
```

产物在 `build/libs/`。

用 IntelliJ 直接打开项目目录通常会自动处理 Wrapper。

### 3. 依赖是怎么处理的

| 模组 | 方式 | 打进产物 |
|---|---|---|
| Flashback | `modCompileOnly` + `depends` 声明 | 否 |
| Fabric API | `modImplementation` | 否 |
| Spatial GUI | 反射调用，非依赖 | 否 |

产物 jar 只含本模组自身代码。`.gitignore` 已排除 `libs/*.jar`，避免误将 Flashback 提交到仓库（ARR 许可不允许分发）。

### 项目结构

| 包 | 职责 |
|---|---|
| `codec/` | 数据模型与编解码 |
| `action/` | 写入 Flashback 的 Action |
| `net/` | 服务端到观看者的 payload |
| `record/` | 采样与写入 |
| `playback/` | 状态缓存、界面重建、tick 驱动 |
| `compat/` | Spatial GUI 反射联动 |
| `mixin/` | accessor 与注入 |
| `log/` | 日志与启动自检 |

### 修改时务必复查的约束

这几条来自 Flashback 源码层面的强制要求，违反会导致崩溃或**静默失效**：

1. Action 名必须以 `optional` 结尾 —— 否则没装本模组的人打开回放会崩溃
2. handler 必须字节级读满缓冲区 —— 多读少读都会抛异常中断回放
3. 绝不能在 payload receiver 内打开界面 —— Flashback 会在处理前后还原 screen，界面开了立刻被关且无任何报错
4. Action handler 运行在回放服务端 —— 必须自行转发给观看者
5. 必须拦截输入 —— 否则会向回放服务端发送它不认识的容器 ID
6. 容器 ID 使用 200+ —— 避开原版 0–99 的循环区间

代码内每条都有注释说明原因。

## 六、验证状态

本版本**尚未完成实测**。建议按以下顺序验证：

1. 录 10 秒开箱回放并打开 —— 界面自动出现、物品正确
2. 不装本模组打开他人录的回放 —— 正常打开不崩溃
3. 回放中点击物品、按 Esc —— 无反应、不发包
4. 装上 Spatial GUI —— 界面以 3D 面板呈现
5. 自由运镜绕行 —— 面板立在世界里
6. 拖动进度条跳转 —— 状态正确、不闪屏
7. 导出视频 —— 界面正常出现

第 1 项通过即说明整条链路可用。

## 七、多版本

当前分支为单版本（1.21.1）。如需适配多个版本，建议引入 **stonecutter** 共用一套源码，用 `//? if` 处理版本差异。已知的跨版本差异：

- `Identifier`（26.x）与 `ResourceLocation`（1.21.x）
- `client.screen` 与 `client.gui.screen()`（26.2 分界）
- `mainCamera()` 与 `getMainCamera()`（26.2 分界）

本模组只依赖 Flashback 自 0.39.0 起稳定的 API，Flashback 小版本升级通常无需改动代码。
